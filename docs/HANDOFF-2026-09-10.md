## What this project is

A personal fork of [Sanctuary](https://github.com/Open-Source-Free-Realms/Sanctuary), the community's C# server
emulator for Free Realms (SOE, 2009-2014, shut down 2014-03-31). Upstream is deliberately a faithful,
multiplayer-oriented emulator with a strict no-AI-authored-code policy. **This fork has different goals:**

- Single-player-first. A world one person can run locally and actually play.
- Faithful where the original data survives, our own design where it is lost (XP curves, loot, quests).
- AI-assisted end to end: code, UI design, 2D art, audio, dialogue.
- Upstream compatibility is not a goal. We track upstream only to cherry-pick fixes and open PRs.

Because of that last point we do not send pull requests upstream, so their AI policy is not in conflict with
anything we do here. Their code is AGPL-3.0 and so is ours.

### 2. The game runs end to end

`.\run_local.ps1` builds, starts the asset server plus the three game servers in their own windows, then
launches the client. Verified 2026-09-10: character creation, world load, walking around, teleport stones,
town transitions, the map.

| Process | Port | Notes |
|---|---|---|
| Sanctuary.Login | UDP 20042 (client), UDP 20041 (gateway link) | Runs EF migrations on start, so the SQLite DB self-creates |
| Sanctuary.Gateway | UDP 20260 | Loads the FabledRealms map (2,019 nodes), Lua scripts, 9 chat commands |
| Sanctuary.WebAPI | HTTP 5000 | `/login`, `/register`, `/image`. Binds 5000, not the 20040 in `appsettings.json`, because when run with cwd=`src/` the config file is not on the content root |
| tools/asset-server | HTTP 20050 | Ours; see below |

Default test account is `test` / `testtest`; `run_client.py` registers it automatically. Note the client
allows only **one** instance — a second `FreeRealms.exe` exits immediately.

### 3. Local asset-delivery server (the main new capability)

The client ships ~470 MB of pack files and **streams everything else over HTTP at runtime** — models,
textures, animations, sounds, effects, UI art. Without an asset server it exits during startup. Upstream's
default host (`osfr.editz.dev`) was returning Cloudflare 523 errors, which is why the client would not start
at all at the beginning of the session.

`tools/asset-server/server.py` (port 20050) now sits in that role:

- Serves from `asset-cache/`; on a miss it fetches from an upstream community host, caches, and serves. The
  cache fills itself as you play.
- **Overrides**: a file dropped in `asset-cache/_overrides/<exact asset name>` is served instead of the
  original. This is the delivery mechanism for custom loading screens, UI art, textures, and NPC voice lines —
  no exe patching, no repacking.
- `asset-cache/_index.txt` records every `NNN/name` path fetched.

Protocol, reverse-engineered this session and documented in the tool's README:

| Request | Response |
|---|---|
| `GET /manifest.crc` | `"<crc32>,<size>"` of the uncompressed manifest (standard reflected CRC-32) |
| `GET /manifest.txt.z` | 8-byte header `A1 B2 C3 D4` + big-endian uncompressed size, then a zlib stream. Lines are `name[.z],crc32,compressed_size` — **162,652 assets, 3.82 GiB** |
| `GET /NNN/<name>.z?<crc32>` | The asset, same framing for `.z` files, raw otherwise |

### 4. Research: what survived of the game

Two research agents swept the wikis, archives, and GitHub. Findings summarised in `research/README.md`, with
raw wikitext committed under `research/wiki/`: **52 quests with verbatim NPC dialogue**, all 17 job pages with
per-level abilities and trainer chains, 20+ town pages, and category lists (537 NPCs, 133 merchants, 95
enemies, 44 dungeons).

**Recoverable:** the full item table, every in-game string (via the client's locale files), the job and
ability structure, town geography, and ~3,500 real NPC placements decoded from 2010-era packet captures.

**Lost for good:** the XP/star curve, coin and loot tables, mob stats and AI, dungeon scripting, minigame
rules, and the text of several hundred quests. Those we design ourselves.

### 5. Ecosystem survey

The most useful findings, in order of impact:

- **Upstream has the hard parts drafted in open PRs**: #109 quests (JSON quest format, TalkToNpc /
  ReachLocation / Collect goals, quest log table), #120 XP and level-ups, #116 generic zoning, #111 housing
  editor. They are stuck in review there. We can cherry-pick them.
- **Loading screens are a data swap.** The client picks from a weighted list in `LoadingScreen.xml` with tip
  StringIds, and **loose files in the client folder override packed assets**. No code needed.
- **`soir20/oxide`** is a Rust server for Clone Wars Adventures — a different game on the same SOE engine —
  and is the most feature-complete server in the family (dialogue with camera and choices, combat, housing,
  navmesh, minigames). Not drop-in, but the best architecture to study, and its asset server is the only
  complete open reference implementation.
- **`mercish/TCG-Files`** contains a working Free Realms asset server in JavaScript, including workarounds for
  assets that 404 on the community CDN (housing, minigames).
- **`yungcomputerchair/free-realms-re`** documents 343 packets across 63 families, and
  **`free-realms-ai-decomp`** is a Ghidra decompilation of the entire client, one file per function. Between
  them, any packet layout can be looked up.

**Licensing caution:** Sanctuary, oxide, FabledRealms and fr-adr-toolkit are AGPL-3.0 and compatible.
FreeRealmsUnpacker, free-realms-re, free-realms-ai-decomp and TCG-Files have **no license** — reference only,
do not copy code. FreeRealmsLocaleTools and ForgeLightToolkit are MIT.

## Findings that shaped the plan

Playing the current build showed exactly why it feels dead:

- **Every job starts at level 20.** Hard-coded in `src/Sanctuary.Game/Helpers/ProfileHelper.cs:73`. There is no
  XP or progression system at all.
- **NPCs cannot be clicked.** The interaction system has six interactions, all player-to-player (add friend,
  guild invite, ignore, inspect). There is no dialogue system. The only NPC script shouts a canned line on a
  timer.
- **Housing purchase fails** with a support error. The housing handler implements edit mode only; the purchase
  packet handlers are stubs that answer country and currency lookups.
- **The gateway drops dozens of packet types silently.** The general shape of the project: the client asks for
  everything the 2014 game did, and the server answers a fraction.
- **Loading screens are Station Cash advertisements** for a store that has not existed since 2014.
