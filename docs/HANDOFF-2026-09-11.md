## Decisions (Carlos, 2026-09-11)

- **Remaster, not reimagine.** Reference = final live build (client v1.910, 2014). Change only quality of life and
  the server-side gaps Sony left. Model: the 2025 Oblivion remaster.
- **Economy is the exception**: open to redesign into a real earn-and-unlock loop (coins from quests and activities,
  unlocks gated by level). Brainstorm before building.
- **Offline game first.** Carlos is effectively remaking Free Realms as a single-player offline game. Public hosting
  only much later, and only if it gains popularity.
- **Canonical new-player path = the March 2013 "NPX 4.0" flow**: Darkthorne's Briarwood Caverns tutorial →
  Farnum's Farm → Cobblestone Village (Bartle vs Mac's hooligans, Cobblestone Showdown) → Queen Valerian in
  Sanctuary. The 2009 Sacred Glade tutorial becomes a later optional "classic start".
- **Dev commands stay, admin-only**, like Skyrim's console. A vanilla player never sees them.
- **Plan defaults accepted** (PLAN-cobblestone.md §5): Sulphural's zone model for instances; their health curve as a
  starting point; crafting stand-ins for the Farnums; new characters start at Farnum's Farm (when that slice lands);
  per-character world state; authentic fixed coin rewards before any loot economy; seasonal NPCs only in season.
- **Faithfulness of NPC lines:** only each character's own authentic lines. No generic greeting pool, no invented
  dialogue where the original's exists.

## Reverse-engineering findings (keep; hard-won)

| Thing | Finding |
|---|---|
| String table | `client/locale/en_us_data.dat` = `hash\ttag\ttext`; hash = Jenkins lookup2 of `Global.Text.<id>`. `tools/locale/extract_strings.py` → `research/strings/en_us.json` (113,286 strings, git-ignored, regenerable in ~30 s). |
| Conversation window | `CommandPacketShowDialog` (26/3). Each response = `{Id, ActionType, LabelTextId, Param1 = icon image id, Param2 = button image set}`. Zeros there draw an "OOPS" placeholder banner. Zero camera vectors + a focus float (1.0) let the client frame the NPC. Client closing the window sends 26/4 (also as an acknowledgement after the server ends a dialog). |
| Quest window | `QuestInfoPacket` (49/1) opens the quest card with rewards and accept/decline. |
| Levelling | `ClientUpdatePacketUpdateProfileRank` (38/18) = 4 ints: profile, rank, icon id, name id. Full-screen celebration = `ClientUpdatePacketJobLevelUp` (38/15) carrying a length-prefixed serialized `ClientPcProfile`; the client's handler (`FUN_009392c0`, a 32-case switch on the ClientUpdate sub-opcode) calls the UI script event `JobLevelUp` unconditionally. The client ignores 38/14 (experience) per Sulphural. Burst effect = composite effect 15117 `PFX_levelup_big`, sent ~300 ms later. A profile re-send clears the ability toolbar; re-send it (`Player.SendToolbar`). |
| NPC cursor | `PlayerUpdatePacketNpcRelevance` entry wire order = `Guid, bool (always true), CursorId, HasCursor`. Upstream had HasCursor in the first slot. `Cursors.txt` ids 13 and 14 name talk-cursor files the client does not ship; a missing file shows no cursor at all. Use id 5 (`cursor_talk.cur`). |
| Bubbles | `ChatPacketFromStringId` with `IsChatLogged=false` = over-head bubble only. The client renders `<BR>` but not `<font>` in bubbles. |
| About Me "levels gained" | Client sums every job's levels above 1. |
| Client scripts | `client/UI/ScriptsBase.bin` is compiled Lua; string-scan it for handler names (e.g. `NotificationHandler:JobLevelUp`). Disassemble `FreeRealms.exe` with Python `capstone` (installed); the Ghidra decomp (yungcomputerchair/free-realms-ai-decomp) misses some functions. |
| Captures | `research/npc-spawns` data is from 2014-03-25/31 (final week), not 2010. 3,475 of 3,521 NPCs spawn in idle animation 1; decoded sessions show NPCs walking, gesturing, looking at players, and NPC pairs trading lines every 4–5 s. |
